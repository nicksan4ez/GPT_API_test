# Улучшенное техническое задание: Система анализа Telegram-каналов

## 1. Общая архитектура

Система должна состоять из следующих модулей:
- Клиентская часть (Telegram-бот)
- Серверная часть (API)
- Модуль сбора данных из Telegram
- Модуль анализа данных с использованием ИИ
- База данных PostgreSQL
- Брокер сообщений (например, RabbitMQ/Kafka)

## 2. Клиентская часть (Telegram-бот)

### 2.1 Функциональность:
- **Ролевая система**: админ и обычный пользователь
- **Интерфейс пользователя**: меню с кнопками, инструкции, процесс анализа
- **Взаимодействие с серверной частью** через API

### 2.2 Пользовательский сценарий:
1. **Начало работы**:
   - При нажатии `/start` проверка прав доступа
   - При наличии доступа: приветствие, кнопки "Инструкция" и "Добавить канал"

2. **Процесс анализа канала**:
   - Запрос ссылки на канал
   - Проверка доступности канала
   - Отображение параметров: канал, глубина анализа (по умолчанию 1000)
   - Кнопки "Запустить анализ" и "Изменить глубину"
   - Получение времени выполнения с сервера
   - Подтверждение запуска

3. **Админ-функции**:
   - Управление пользователями (предоставление/отзыв доступа)
   - Просмотр статистики использования системы

## 3. Серверная часть (API)

### 3.1 Технический стек:
- FastAPI/Flask
- SQLAlchemy 2.0
- Pydantic для валидации
- PostgreSQL

### 3.2 Основные эндпоинты:
- Авторизация/аутентификация пользователей
- Проверка доступности канала
- Оценка времени выполнения анализа
- Запуск анализа канала
- Получение результатов анализа
- Управление пользователями (для админов)

### 3.3 Логика работы:
1. Получение и валидация запросов от бота
2. Координация работы модулей сбора и анализа данных
3. Пакетная обработка: разбиение на группы по 100 сообщений
4. Асинхронная обработка с использованием брокера сообщений

## 4. Модуль сбора данных из Telegram

### 4.1 Функциональность:
- Получение сообщений канала с указанной глубиной
- Получение комментариев к сообщениям
- Сбор метаданных медиафайлов (ссылки, типы)

### 4.2 Архитектура:
- Независимые обработчики для сообщений и комментариев
- Возможность параллельной обработки
- Обработка ограничений API Telegram
- Работа через Telegram Client API (например, Telethon/Pyrogram)

## 5. Модуль анализа данных с использованием ИИ

### 5.1 Технологический стек:
- Фреймворк Crew AI для создания мультиагентной системы
- LangChain для интеграции с языковыми моделями
- OpenAI API или другие LLM (для работы агентов)
- Pandas для обработки структурированных данных
- NLTK/spaCy для базовой обработки текста
- Matplotlib/Plotly для визуализаций

### 5.2 Архитектура модуля:
- **Менеджер агентов** - управляет работой аналитических агентов
- **Специализированные агенты**:
  1. **Аналитик тональности** - определяет эмоциональный окрас сообщений
  2. **Тематический аналитик** - выявляет основные темы и кластеры
  3. **Аналитик ключевых слов** - выделяет ключевые слова и фразы
  4. **Статистический аналитик** - анализирует числовые показатели активности
  5. **Составитель отчетов** - формирует итоговый отчет

### 5.3 Функциональность агентов:
- **Аналитик тональности**:
  - Определение общей тональности канала
  - Выявление динамики изменения настроений
  - Анализ эмоциональной окраски комментариев

- **Тематический аналитик**:
  - Выделение 5-10 основных тематических кластеров
  - Определение ключевых характеристик каждой темы
  - Анализ изменения популярности тем во времени

- **Аналитик ключевых слов**:
  - Составление рейтинга самых употребляемых слов
  - Выделение специфичных для канала терминов
  - Анализ частотности употребления по времени

- **Статистический аналитик**:
  - Анализ частоты публикаций
  - Подсчет показателей взаимодействия
  - Выявление закономерностей в активности

### 5.4 Процесс работы модуля:
1. Получение данных от модуля сбора
2. Распределение задач между агентами
3. Параллельная аналитическая работа агентов
4. Формирование отчета агентом-составителем
5. Передача результата на серверную часть

### 5.5 Форма отчета:
- Общая статистика канала (подписчики, активность, частота публикаций)
- Анализ тональности сообщений и комментариев
- Популярные темы и их характеристики
- Ключевые слова и фразы с частотой упоминания
- Анализ взаимодействия аудитории
- Графики и визуализации для наглядного представления
- Выводы и рекомендации по контент-стратегии

### 5.6 Интеграция с другими модулями:
- Асинхронное получение данных через брокер сообщений
- Сохранение результатов анализа в базу данных
- Кэширование для оптимизации повторных запросов
- API для получения результатов анализа клиентской частью

## 6. База данных

- Хранение данных о пользователях и их ролях
- Хранение истории запросов и результатов анализа
- Кэширование данных для оптимизации повторных запросов

## 7. Брокер сообщений

- Обеспечение асинхронного взаимодействия между модулями
- Балансировка нагрузки при параллельной обработке
- Очереди задач для сбора и анализа данных

## 8. Требования к безопасности и производительности

- Защита API с использованием JWT-токенов
- Ограничение количества запросов от одного пользователя
- Оптимизация хранения и обработки больших объемов данных
- Масштабируемость системы при росте нагрузки
